# OpenDeck V2 Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Ship OpenDeck 2.0: module-scoped variables, a kiosk-style mobile PWA, a richer module API (lifecycle, state, option providers) with first-class OBS and Elgato Wave Link modules, a full per-button editor, and live button faces driven by module state, HTTP values, or image URLs.

**Architecture:** The Electron main process stays the single source of truth. Modules gain a context object (`ctx`) that scopes settings to the owning module, lets them publish state, and lets them answer option queries (scenes, inputs, channels). State flows to every client over the existing WebSocket as `state.snapshot` / `state.update`, and buttons resolve their face from that state on the client. The renderer gets a kiosk mode for remote devices (wake lock, auto fullscreen, PWA manifest) and a tabbed per-button editor with drag and drop.

**Tech Stack:** Electron 28, React 18, Vite 5, Express 4, ws, obs-websocket-js 5, TypeScript 5.3. Wave Link 3 uses its local JSON-RPC 2.0 WebSocket (port from `ws-info.json`, fallback scan 1884–1893, header `Origin: streamdeck://`).

---

## Current context

- Variables are global: `action-dispatcher.ts` injects `variableStore.toRecord()` as `payload.__variables` into every handler.
- Modules are plain `{ actions }` objects; no init/dispose, no state, no settings schema.
- `useDeckConfig.tsx` holds pages/variables/displayImage, persists to localStorage, and pushes to the server from Electron only.
- Mobile: `useWakeLock` and `useFullscreen` exist but fullscreen is a manual button and there is no PWA manifest.
- Button editor is a single scrolling form inside a fixed inspector; no DnD, no copy/paste, no press modes.
- OBS module connects lazily per action, no events. No Wave Link module.

## Assumptions

- Target Wave Link **3.x** (current protocol). Wave Link 1.x/2.x used port 1824 and different method names; not supported.
- Windows is the primary platform (existing modules already assume it).
- Remote devices stay read-only; only loopback connections may update config.

## Phase 1: Shared types and module API v2

### Task 1.1: Extend shared types
**Files:** Modify `app/shared/types/actions.ts`, `app/shared/types/modules.ts`, `app/shared/types/messages.ts`

- `DeckVariable` gains `module?: string` (empty = unassigned/legacy).
- `DeckButton` gains `disabled?`, `face?: ButtonFace`, `pressMode?: "tap"|"hold"|"long"`, `releaseAction?`, `longPressAction?`, `sequence?: ButtonAction[]`.
- `ButtonFace`: `color`, `textColor`, `labelPosition`, `fontSize`, `imageTemplate`, `labelTemplate`, `source?: { type:"http"; url; path?; intervalMs? }`, `states?: ButtonFaceState[]`.
- `DeckPage` gains `columns?`, `rows?`.
- `ModuleManifest` gains `config?: Record<string, ParamDefinition>`, `apiVersion?`.
- `SelectParam` gains `optionsFrom?: string`, `dependsOn?: string`, `allowCustom?: boolean`.
- `ModuleContext` interface: `settings`, `setState`, `getState`, `setStatus`, `log`.
- `OpenDeckModule` gains `init?`, `dispose?`, `onSettingsChanged?`, `providers?`.
- Messages: server `state.snapshot`, `state.update`, `module.status`; client `button.press` payload carries `__pressType`.

### Task 1.2: State store
**Files:** Create `app/electron/state-store.ts`

Map of `"module.key" -> value`, `set()` returns whether changed, `snapshot()`, `onChange` listener used by server to broadcast.

### Task 1.3: Module registry with contexts
**Files:** Modify `app/electron/module-loader.ts`

- Build a `ModuleContext` per module (settings from `variableStore.forModule(name)`).
- Call `init(ctx)` after load; `dispose()` on reload; `onSettingsChanged(ctx)` when variables change.
- Expose `getProviderOptions(moduleName, provider, arg)`.
- Loading twice skips already-registered modules (plugin install path).

### Task 1.4: Scoped variable store and dispatcher
**Files:** Modify `app/electron/variable-store.ts`, `app/electron/action-dispatcher.ts`

- `forModule(name)` returns only that module's variables as a record.
- Dispatcher passes `{...payload, __variables: scoped}` plus `ctx` as second arg.
- Legacy migration in `config-store.ts`: `obs_host`→obs-control `host`, `obs_password`→obs-control `password`.

### Task 1.5: Server endpoints and broadcasts
**Files:** Modify `app/electron/server.ts`

- `GET /api/modules` includes `config`, `status`.
- `GET /api/modules/:name/options/:provider?arg=`.
- `GET /api/state`.
- On connect send `state.snapshot`; on store change broadcast `state.update`.
- Reject `config.update` from non-loopback sockets.
- Face poller: for every button with `face.source.type === "http"`, fetch on interval, publish `button.<id>.value`.

**Verify:** `npm run build:electron` passes.

## Risks

- Wave Link protocol is reverse-engineered; method shapes may differ per version. Client logs raw errors and the Modules page shows status.
- iOS Safari only honours the Wake Lock API in 16.4+; older devices will still sleep.
- Base64 images in config can make `state`/config messages large; faces resolved from URLs avoid this.
